FirmGen Product Requirement Document (PRD)

Project: SPAN-ESP32 (SentinelAI Safety Actuator Node)

Target Hardware: ESP32-WROOM-32 / ESP32-S3
Framework: ESP-IDF v5.5
Execution Path: FirmGen Category-wise Review & Build
Status: APPROVED & READY

1. Vision & Purpose

SPAN-ESP32 is an industrial edge safety node responsible for deterministic, physical actuation when hazard warnings or intrusion alerts are signaled by upstream perception nodes (PipeGen). It eliminates latency and reliability risks inherent in purely cloud-driven safety systems by providing local, hardware-level machinery cut-offs and strobe alerts.

3. Functional Requirements (FR)

[FR-01] Structured JSON Ingestion

The firmware MUST parse newline-terminated (\n) JSON strings from UART0 containing event, severity, and optional zone_id fields.

{"event": "ZONE_BREACH", "severity": "CRITICAL", "zone_id": 1, "timestamp": 1710000000}

[FR-02] Critical Hazard Actuation

Upon receiving event == "ZONE_BREACH":

  • GPIO 4 (Strobe) toggles at 5Hz (100ms ON / 100ms OFF).
  • GPIO 18 (Buzzer) sounds with a pulsed tone.
  • GPIO 19 (Safety Relay) drops to LOW (tripping machinery circuit).
  • Response latency must be under 20ms from packet arrival.

[FR-03] Warning Status Indication

Upon receiving event == "NO_PPE":

  • GPIO 2 (Status LED) blinks at 1Hz (500ms ON / 500ms OFF).
  • GPIO 19 remains HIGH (machinery stays running).

[FR-04] Manual Operator Reset

Pressing the physical push button on GPIO 0 for at least 50ms MUST reset the alarm state back to IDLE (Relay HIGH, Strobe/Buzzer OFF).

[FR-05] BLE GATT Telemetry Advertising

ESP32 MUST host a BLE GATT Server advertising custom service UUID 4fafc201-1fb5-459e-8fcc-c5c9c331914b exposing read/notify characteristics for current state and incident tally.

[FR-06] Heartbeat & System Health

System MUST emit periodic telemetry over UART every 2000ms in JSON format:

{"telemetry": {"state": 0, "incidents": 2, "heap": 224180}}
